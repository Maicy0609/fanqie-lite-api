# 客户端迁移方案（Phase 6）

> 目标：把 fqapp 的 Dart 前端从"进程内 FFI 调 Rust 核心"改为"HTTP 调本项目的服务端"，
> 让同一份前端可以跑多平台，并让服务端成为唯一的后端实现。
> 本文只做方案与工作量评估，不含实现。

---

## 1. 结论：量不大

**Dart 侧约 350 行改动，集中在 5 个文件；不含设置页约 190 行。**

对比一下量级：后端移植改了 18,000 行里的 500–900 行（3–5%）；客户端迁移是 20,000 行
Dart 里的 350 行（约 1.7%）。

之所以这么小，是因为上游已经把传输层抽象好了，而且抽象得刚好对：

| 证据 | 位置 |
|---|---|
| `rust.`（FFI 符号）**只出现在一个文件** | `lib/services/backend_transport.dart`，8 个调用 |
| 启动流程**已按传输类型分支** | `backend_service.dart:212` `if (rustTransport is RustBackendTransport)` |
| HTTP 传输**已存在** | `HttpBackendTransport`（测试/桌面/Web 在用） |
| `http` 包**已是依赖** | `pubspec.yaml` `http: ^1.6.0` |
| 生成的绑定只有 870 行 | `lib/src/rust/` 两个文件 |

也就是说：**不需要重写前端**，只需要把 `RustBackendTransport` 换成
`HttpBackendTransport`，并修好两处"只有 FFI 才成立"的假设。

---

## 2. 要改什么

### 2.1 五处改动

| # | 文件 | 改什么 | 估算 |
|---|---|---|---|
| 1 | `services/backend_transport.dart` | 远程传输：Bearer 令牌、媒体 URL 带 `?token=`。可扩展现有 `HttpBackendTransport`，也可新增一个 | ~80 行 |
| 2 | `services/backend_service.dart` | 按配置选传输；远程模式跳过 `_deploy()` 与核心初始化；健康检查改 `/readyz` 并放宽超时 | ~50 行 |
| 3 | `services/api_client.dart` | `absoluteUrl()` 改为委托给 `transport.mediaUrl()`，不再自己拼 `/_session/<cap>/` | ~25 行 |
| 4 | 配置 + 设置页 | base URL、令牌的存储与入口（可先用 `--dart-define` 压到 ~20 行） | ~20 / ~180 行 |
| 5 | `services/fanqie_library_capture_service.dart` | 远程模式默认隐藏账号采集入口 | ~15 行 |

### 2.2 两处"只有 FFI 才成立"的假设

这是真正需要动脑的地方，其余都是机械替换。

**假设一：媒体 URL 里带 capability。**

现在 `absoluteUrl('/src/x.mp4')` 拼成 `http://127.0.0.1:18921/_session/<cap>/src/x.mp4`
（capability 在路径里）。远程服务的契约是 `http://host:18921/src/x.mp4?token=<token>`。

改法：把"怎么拼媒体 URL"收进 transport 的一个方法，`api_client` 只调它。
这样 6 个 `resolveBackendResource` 调用点和 13 个 `absoluteUrl` 调用点**一个都不用动**。

**假设二：后端和前端在同一台机器上。**

远程模式下：

- `_deploy()`（把 `config.json`/`filter.json`/`device_pool.json` 拷到应用目录）没有意义，跳过。
- `readRustLog()`（读本机 `rust.log`）要返回 null，日志页显示"远程模式无本地日志"。
- 健康检查轮询 `/health` 15 秒不够：服务端冷启动要注册 5 个设备（每个含 2 秒停顿），
  约 20 秒。应改轮询 `/readyz`，超时放到 40–60 秒。

---

## 3. 不需要改什么

这些全部是 Dart 侧逻辑，与传输无关，**一行不用动**：

本地数据（Hive 书架/进度/划线/设置）、阅读器排版与翻页、播放器 UI 与手势、
下载管理器、TTS、正文替换、TXT/EPUB 导入、搜索历史、榜单缓存、图片缓存策略、
备份恢复、主题、无障碍。

**`native/`（C 解密库）保留。** 它由 `NativePlayerPlugin.kt` 通过 JNI 直接调用，
和 Rust 核心无关——`mode=stream` 的 CENC 解密路径在迁移后照常工作。

---

## 4. 两个方案

| | **A. 双模式** | **B. 纯远程** |
|---|---|---|
| 内容 | 保留 FFI 单机模式，新增远程模式，按配置切换 | A 的全部 + 删除 FFI |
| 改动量 | ~350 行 | ~350 行 + 删除 870 行绑定、pubspec 的 FRB 依赖、`rust/`、构建脚本 |
| 离线 | 保留单机能力 | 首次启动必须能连到服务器 |
| 构建复杂度 | 不变（仍需 NDK + cargo） | 大幅下降（不再需要交叉编译 Rust） |
| 风险 | 低 | 中：要逐条验证"没有核心也能跑" |

**建议先做 A。** 理由：

1. A 已经满足"多平台 + 前后端分离"的目标——同一份 Dart，换一个 transport 而已。
2. A 可以灰度：先用 `--dart-define` 指向服务器，跑通再做成设置项。
3. 删 FFI 是独立的、可回退的一步，等 A 稳定后单独做，不必现在承担风险。

## 5. 四个关键设计点

### 5.1 播放路径不变

`GET /api/v1/videos/{id}?mode=stream` 返回 `{video_url, key_hex, variants[]}`，
客户端仍用 C 库在本地解 CENC。**服务端不为播放做额外工作，也不占磁盘。**

如果客户端改用不带 `mode` 的默认路径，服务端会下载并解密整集再返回 `/src/...`——
适合"要离线/要缓存"，但首帧慢、占服务器带宽。两种都在，由客户端选。

### 5.2 账号采集要默认关闭

`POST /api/v1/account/fanqie/*` 会把用户的番茄账号 Cookie 发给服务器。单机模式下
Cookie 只在本机内存里用；远程模式下它离开设备了。

这不是技术问题，是产品边界问题。建议：**远程模式下隐藏该入口**，并在文档里说明原因。
如果确实需要，至少要在 UI 上明确告知"Cookie 会发送到你配置的服务器"。

### 5.3 并发与容量

服务端单实例共享 5–20 个设备身份。原项目是"一个用户 + 16 并发闸门"；接多客户端后，
上游按 `device_id` 限流会先撞上。客户端侧应保留现有 `RequestGate`（相同 GET 合并、
最多 16 并发），不要因为"现在是 HTTP"就放开。

### 5.4 冷启动体验

首次连服务器时 `/readyz` 可能 503 达 20 秒。启动页文案要能区分"连不上服务器"和
"服务器正在注册设备"，否则用户只会看到"一直转圈"。

## 6. 分阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P6.0** | 远程传输 + 媒体 URL + 启动分支。用 `--dart-define=FQ_API_BASE=...` / `FQ_API_TOKEN=...` 配置，不做 UI | 能对远程服务器搜索、看目录、读正文、播放短剧、看漫画 |
| **P6.1** | 设置页：base URL + 令牌 + "测试连接"按钮（打 `/healthz` 与 `/readyz`） | 不重新打包也能改服务器地址 |
| **P6.2** | 远程模式降级项：账号采集隐藏、日志页提示、启动页区分错误类型 | 远程模式下没有指向本机的死链 |
| **P6.3**（可选） | 删除 FFI：`lib/src/rust/`、pubspec、`rust/`、构建脚本 | `flutter build apk` 不再需要 NDK/cargo |

P6.0 是关键路径；P6.1–P6.2 是体验；P6.3 是净化，可以无限期推迟。

---

## 7. 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 服务端成为单点 | 服务器挂了前端全挂（单机模式没有这个问题） | 方案 A 保留单机模式兜底 |
| 并发被上游限流 | 多客户端共享设备池 | 保留 `RequestGate`；服务端已有全局信号量 |
| 冷启动 20 秒 | 首次连服务器要等 | `/readyz` + 启动页文案 |
| 带宽转移 | 下载/播放的流量从"手机直连 CDN"变成"经过服务器" | 播放用 `mode=stream` 直连 CDN；下载才走服务器 |
| 隐私面变化 | 原项目内容直连上游；迁移后所有请求经服务器 | 自建自用可接受；对外提供服务需重新评估 |
| 账号 Cookie | 远程模式下离开设备 | 默认关闭该入口 |

## 8. 工作量小结

| 项 | 估算 |
|---|---|
| Dart 代码改动 | ~190 行（不含设置页）/ ~370 行（含） |
| 涉及文件 | 5 个（含设置页 7 个） |
| 需要新写的测试 | 传输层的 URL 拼装与错误映射（Dart 单测）；一次真机端到端 |
| 不需要动的代码 | ~19,600 行 Dart（阅读器、播放器、本地存储、下载、TTS 等） |

**一句话**：这是"换一根线"，不是"重写前端"。真正的成本在验证——要逐条确认阅读、
播放、下载、离线、账号导入在远程模式下都还成立。
